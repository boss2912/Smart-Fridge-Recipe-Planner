## 🎯 Smart Fridge คืออะไร

หลายครัวเรือนใช้ระบบนี้ร่วมกัน ของที่ซื้อเข้าตู้ สมาชิกแต่ละบ้านจะบันทึกเป็นล็อต พร้อมวันซื้อ วันหมดอายุ และจำนวน จากนั้นระบบก็เตือนของที่ใกล้หมดอายุ และแนะนำเมนูที่ทำได้จากของที่ยังเหลืออยู่ในตู้

### ของในตู้เข้าทางเดียว ออกได้สองทาง

```text
ซื้อ ──► ล็อตในตู้ (วันซื้อ / วันหมดอายุ / จำนวน)
            │
            ├──► ทำอาหาร ──► ระบบหักวัตถุดิบตามสูตร
            │
            └──► ทิ้ง (หมดอายุหรือเสีย) ──► หักจากล็อตนั้น และเก็บประวัติการทิ้ง
```

จำนวนในตู้จึงเท่ากับของที่ซื้อ หักของที่ใช้ทำอาหาร และหักของที่ทิ้ง ถ้าไม่บันทึกทางออกทางใดทางหนึ่ง จำนวนในตู้จะมากกว่าของจริงไปเรื่อยๆ ระบบก็จะแนะนำเมนูที่ของหมดไปแล้ว

### ผู้ใช้ 2 กลุ่ม

| ผู้ใช้ | ทำอะไรได้ |
|---|---|
| สมาชิกในครัวเรือน | บันทึกของที่ซื้อเข้าตู้ · บันทึกว่าทำเมนูไหน · บันทึกของที่ทิ้ง · ดูคำเตือนและเมนูที่ทำได้ |
| ผู้ดูแลระบบ | เพิ่มและแก้ไขรายการวัตถุดิบและสูตรอาหารกลางที่ทุกบ้านใช้ร่วมกัน · ดูบ้านทุกบ้านและของในตู้ · ปิดบัญชีบ้าน ([ADR-015](docs/DECISIONS.md#adr-015--ผู้ดูแลระบบดูได้ทุกบ้านและปิดบัญชีบ้านได้)) |

### ข้อมูลหลัก 7 อย่าง

1. ข้อมูลครัวเรือน (บัญชีบ้าน)
2. ข้อมูลหมวดหมู่และวัตถุดิบ (หน่วยมาตรฐาน)
3. ข้อมูลของในตู้แต่ละล็อต (วันซื้อ/วันหมดอายุ/จำนวน)
4. ข้อมูลสูตรอาหาร
5. วัตถุดิบที่ใช้ในแต่ละสูตร (ปริมาณ)
6. ประวัติการทำอาหาร
7. ประวัติการทิ้งของ (ล็อต/จำนวน/วันที่ทิ้ง)

ไม่เก็บข้อมูลสมาชิก ทุกคนในบ้านใช้บัญชีเดียวและประวัติเป็นของบ้านรวมกัน ([ADR-010](docs/DECISIONS.md#adr-010--บ้านหนึ่งมีบัญชีเดียว-ทุกคนในบ้านใช้ร่วมกัน)) ต่างจาก proposal ที่ส่งไปซึ่งมี 8 อย่าง

รายการซื้อของกับราคาสินค้าไม่อยู่ในขอบเขต เหตุผลอยู่ใน [`docs/DECISIONS.md`](docs/DECISIONS.md)

## 🏗️ สถาปัตยกรรม — Distributed System

ระบบแบ่งเป็น 4 ส่วน คือ Nginx (ทางเข้า) · frontend (หน้าเว็บ) · backend (Flask) · database (DBMS) ผู้ใช้ทั้ง 2 กลุ่มเข้าใช้ผ่านเบราว์เซอร์ · frontend กับ backend รันเป็นโปรแกรม Flask ตัวเดียว ([ADR-009](docs/DECISIONS.md#adr-009--เลือกภาษาและวิธีรันเว็บแอป))

```text
        Browser (สมาชิกในครัวเรือน / ผู้ดูแลระบบ)
                          │
                          ▼
                 ┌─────────────────┐
                 │      Nginx      │  ทางเข้าเดียว
                 └────────┬────────┘
                          ▼
     ┌──────────────────────────────────────────┐
     │  Flask (Python)                          │  frontend กับ backend อยู่ในโปรแกรมเดียว
     │  ┌───────────────┐   ┌───────────────┐   │
     │  │   frontend    │◄──│    backend    │   │
     │  │  HTML CSS JS  │   │  route login  │   │
     │  └───────────────┘   └───────┬───────┘   │
     └──────────────────────────────┼───────────┘
                                    ▼
                           ┌─────────────────┐
                           │    database     │  PostgreSQL
                           └─────────────────┘
```

### แต่ละส่วนต้องมีอะไร

| ส่วน | ต้องมี |
|---|---|
| **Nginx** | ทางเข้าเดียวของระบบ: ส่งต่อทุกคำขอไปที่ Flask · ส่งไฟล์ CSS / JS / รูป ให้เบราว์เซอร์เองได้ |
| **frontend** | หน้าของสมาชิกในครัวเรือน: บันทึกของที่ซื้อเข้าตู้ · บันทึกว่าทำเมนูไหน (+ เครื่องปรุงเพิ่มเติม) · บันทึกของที่ทิ้ง · ดูของใกล้หมดอายุ · ดูเมนูที่ทำได้<br>หน้าของผู้ดูแลระบบ: เพิ่มและแก้ไขรายการวัตถุดิบกับสูตรอาหารกลาง · ดูบ้านทุกบ้านและของในตู้ · ปิดบัญชีบ้าน<br>เขียนเป็น template HTML + CSS ที่ Flask ส่ง · JavaScript เฉพาะที่จำเป็น ([ADR-009](docs/DECISIONS.md#adr-009--เลือกภาษาและวิธีรันเว็บแอป)) |
| **backend** | route ของ Flask ที่ส่งหน้าเว็บและรับฟอร์ม · ล็อกอิน (บ้านที่ถูกปิดล็อกอินไม่ได้) · แยกสิทธิ์ 2 กลุ่ม: วัตถุดิบกับสูตรกลางแก้ได้เฉพาะผู้ดูแลระบบ · บ้านเห็นและทิ้งได้เฉพาะของในตู้บ้านตัวเอง ผู้ดูแลระบบเห็นทุกบ้าน ([ADR-003](docs/DECISIONS.md#adr-003--ต้องมีการบันทึกการทิ้งของ) · [ADR-015](docs/DECISIONS.md#adr-015--ผู้ดูแลระบบดูได้ทุกบ้านและปิดบัญชีบ้านได้)) |
| **database** | ข้อมูลหลัก 7 อย่าง · PK / FK / NOT NULL / UNIQUE ตามตัวอย่างหน้า 31 · query 4 เรื่องใน [`database/`](database/) ซึ่งทำอาหารกับทิ้งของต้องอยู่ในธุรกรรมเดียว ([ADR-001](docs/DECISIONS.md#adr-001--ทำอาหารแล้วระบบหักวัตถุดิบตามสูตร) · [ADR-003](docs/DECISIONS.md#adr-003--ต้องมีการบันทึกการทิ้งของ)) · ใช้ PostgreSQL ([ADR-005](docs/DECISIONS.md#adr-005--เลือก-dbms)) |

> งานส่ง 4 ชิ้นของอาจารย์ (Lecture 1 หน้า 11) ไม่มีหน้าเว็บหรือ API ส่วน Nginx · frontend · backend จึงเป็นงานเพิ่มนอกงานส่ง เริ่มพร้อมขั้น 2 ([ADR-008](docs/DECISIONS.md#adr-008--ทำเป็นเว็บแอปที่ใช้งานได้จริง))
